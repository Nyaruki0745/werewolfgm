# WEREWOLF GM

GitHub Pages + GitHub Codespaces だけで動かす、人狼ゲームの進行補助WebアプリのMVPです。外部DB・Supabase・外部API・追加npmパッケージには依存しません。

> **運用上の注意**：GitHub Pagesは画面を公開し、GitHub CodespacesがゲームAPIを実行します。Codespacesは常時稼働サーバーではありません。ゲーム中はホストがCodespaceを起動し、APIを動かし続けてください。Codespaceが停止するとゲームAPIも停止します。

## できること

- ルーム作成・参加（6文字コード、最大20人）
- 主催者もプレイヤーとして参加
- ロビーの準備状態・役職構成設定
- 役職のランダム配布、恋人ペアの自動設定
- 個人ごとの役職・秘密情報表示
- プレイヤー復帰コード（復帰時にコードをローテーション）
- 昼の議論フェーズ・投票・同票処理
- 人狼全員の承認による共同襲撃
- 占い・霊媒・護衛
- 襲撃・護衛・妖狐・恋人後追いの死亡処理
- 村人・人狼・妖狐・てるてる・恋人の勝利判定
- ゲーム一時停止・再開・強制終了
- Codespaces内JSONファイルへの保存
- Node.js標準テスト

## 構成

- `web/`：GitHub Pagesに公開する静的フロントエンド
- `server/`：Node.js標準機能のみで動くAPIとゲームエンジン
- `tests/`：Node.js標準テスト
- `.devcontainer/`：Codespacesの環境設定
- `.github/workflows/pages.yml`：GitHub Pages自動公開
- `.github/workflows/test.yml`：push / pull request時の自動テスト

## 初回セットアップ

### 1. GitHubにリポジトリを作る

GitHubで空のリポジトリを作成してください。GitHub FreeでGitHub Pagesを利用する場合は、リポジトリを **Public** にします。既定ブランチ名は `main` にしてください。

このプロジェクトにはAPIキーやパスワードを含めていません。ゲームの参加トークンや復帰コードは実行時に発行され、サーバーの保存ファイルはGit管理対象外です。

### 2. プロジェクトをリポジトリにアップロード

ZIPを展開し、中身をリポジトリへアップロードするか、ローカルのターミナルで次を実行します。

```bash
git init
git add .
git commit -m "Initial WEREWOLF GM"
git branch -M main
git remote add origin https://github.com/ユーザー名/リポジトリ名.git
git push -u origin main
```

### 3. Codespacesを開く

リポジトリの `Code` → `Codespaces` → `Create codespace on main` を選びます。

Codespacesのターミナルで次を実行します。

```bash
npm start
```

次のように表示されればAPIが起動しています。

```text
WEREWOLF GM API listening on http://0.0.0.0:8787
```

### 4. APIポートを公開する

Codespaces画面下部の `PORTS` タブを開き、`8787` のポートを確認します。ポートのVisibilityを `Public` に変更し、表示された転送URLをコピーします。

このURLがAPIの接続先です。公開ポートはURLを知っている人がアクセスできるため、ゲーム終了後はポートを停止するか、Visibilityを `Private` に戻してください。Codespaceを再起動すると公開設定がPrivateに戻る場合があるため、再起動後はVisibilityも確認してください。

### 5. GitHub Pagesを有効化する

リポジトリの `Settings` → `Pages` → `Build and deployment` で `GitHub Actions` を選びます。

`main` ブランチに `.github/workflows/pages.yml` がある状態でpushすると、GitHub Actionsが `web/` のファイルをGitHub Pagesへ公開します。公開URLは `https://ユーザー名.github.io/リポジトリ名/` の形式です。

### 6. サイトにAPI URLを登録する

GitHub Pagesで公開されたURLを開き、右上の歯車から `ゲームサーバー URL` にCodespacesの転送URLを貼り付けて「保存して接続」を押します。

各プレイヤーも同じGitHub PagesのURLにアクセスし、同じAPI URLを設定します。API URLはブラウザ内に保存されるため、各端末で最初の1回だけ設定してください。

## ゲーム開始まで

1. 主催者がルームを作成し、6文字のルームコードを共有します。
2. 各プレイヤーが参加し、準備完了にします。
3. 主催者が参加人数と役職数の合計を一致させ、ルールを設定します。
4. 全員の準備完了後、主催者がゲームを開始します。
5. 各プレイヤーは自分の役職を確認し、「確認した」を押します。
6. 全員の確認後、昼の議論フェーズに移ります。

初期役職構成は10人用です。参加人数が異なる場合は、ロビーで役職人数を調整してください。恋人は通常役職とは別に付与されます。

## 復帰コード

ルーム参加後、画面上部の「復帰コード」から12文字のコードを確認・コピーできます。端末変更やブラウザの保存データ消失に備えて、各自で安全な場所に保管してください。

復帰時はトップページでルームコードと復帰コードを入力します。復帰に成功すると新しい復帰コードが発行され、以前のコードは無効になります。復帰コードを知っている人はそのプレイヤー枠を引き継げるため、他人に共有しないでください。

## Codespacesでの利用上の注意

- APIプロセスを起動した人のCodespaceが動いている間だけゲームに参加できます。
- Codespacesはアイドル状態などで停止することがあります。ゲーム中はホストがCodespacesを開き、ターミナルのAPIプロセスを維持してください。
- Codespacesが停止・再起動した場合は `npm start` を再実行してください。
- ゲーム状態は `.data/store.json` に保存します。このファイルは `.gitignore` 対象です。GitHubリポジトリにはコミットしないでください。
- Codespace自体を削除すると、`.data` 内のゲームデータも失われます。必要なときは安全な場所にバックアップしてください。
- 公開ポートに接続する場合、ゲーム終了後にポートを閉じてください。
- この方式は少人数の短時間ゲーム向けMVPです。常時稼働・長時間運用・高い可用性を保証する構成ではありません。

## 現在のルール初期値

- 人狼は一晩1人を襲撃。複数人狼は全員承認が必要。
- 騎士は連続護衛不可・自己護衛不可。
- 恋人は1組。片方が死亡すると相方も後追い。
- 妖狐は人狼襲撃を無効化し、占われると死亡。
- 同票は処刑なし。
- 占い・霊媒結果は陣営判定。
- 死亡時の役職公開は無効。
- 投票結果は全員の投票完了後に処理。
- てるてるは投票で処刑されると即時勝利。
- 恋人2人だけが生存した場合は恋人勝利。
- 妖狐が生存したまま村人または人狼の通常勝利条件が成立した場合は妖狐勝利。
- 人狼の勝利判定では人狼の人数と、人狼以外の生存者数を比較する。

ロビーの設定画面で変更可能な項目があります。勝利条件の詳細ルールは、今後のバージョンで設定化できるよう拡張予定です。

## 現時点の制約と今後の改善候補

- 保存方式はCodespacesのローカルJSONファイルです。複数プロセス・複数Codespace間の共有DBではありません。
- APIポート公開は手動で設定します。
- 現在の対応人数は最大20人です。
- 一度のゲーム内で占い師・騎士・妖狐は各1人までです。霊媒師は複数配置できます。
- 投票の再投票は最大1回です。
- 行動タイマーや議論タイマーは未実装です。
- 役職追加は `server/game-engine.mjs` の役職定義・処理と、`web/app.js` の表示情報を追加して行います。
- 本格的な運用に向けては、永続DB、常時稼働サーバー、より詳細な監査ログ・管理機能が必要です。
